## 2. 阶段划分

阶段的目标是"**可验证的完整体验**"，不是"功能清单"。每个阶段结束时都应该能玩一遍并给出结论。

### 阶段 0 — 地基（已完成）
框架 + 基础注册 + 确定性随机 + 客户端幽灵渲染 + 基础网络。
- 交付：`MutationHelper` 纯函数解析、`ClientRenderCache` 幽灵预览、`SectionCompilerMixin` 模型替换
- 完成标志：单机能看到方块失焦且挖下来掉落与看到的一致

### 阶段 1 — 突变池三层模型 + 两时钟（已完成，`2026-09-15` ~ `2026-09-17`）
把"谁失焦 / 变成什么 / 几何约束"拆成三个正交的数据包标签层；把周期抽成"存储时钟 / 显示时钟"两根指针。
- 交付：`mutation/pool/*`、`MutationRandom`、`MutationStateMapper`、`/focaldecay period` 与回滚
- 完成标志：`mutation audit` 的 `frozen/asymmetric/crossClass` 全 0；不收敛测试 256 周期 85 种不同结果

### 阶段 2 — 观测稳定系统（已完成，`2026-08-19` ~ `2026-09-17`）
基座 + 六种观测模型 + 训练终端 + 末地王座与仪式 + 完全稳定锚 + 七枚碎片 + 候选观测者主线。
- 交付：`ObserverModelData`、`MutationPoolManager` 保护/引导、`ThroneRitualHandler`、`ObserverCoreHandler`
- 完成标志：从零存档能走通"训练模型 → 建稳定区 → 收集碎片 → 登座 → 装核心 → 失焦终止"

### 阶段 3 — 联机一致性（已完成，`2026-09-17`）
把"两端一致"从约定变成数据结构。
- 交付：`MutationSettings` + 四条增量/快照包 + `SyncClientViewPacket`
- 完成标志：真·局域网里房主与客人看到同一个世界，挖下去掉落对得上

### 阶段 4 — **稳定与加固（当前阶段）**
不做新玩法，把已知缺陷清掉，把"未实机验证"的项补上。**这一阶段的产出是信心，不是功能。**

优先级按 `BACKLOG.md` 的 P0 → P1 顺序推进。进入下一阶段的条件：

- [ ] P0 全部关闭（8 条）
- [ ] P1 全部关闭或明确降级为"接受的设计取舍"并写进 `DESIGN.md` §14
- [ ] `AGENTS.md` §4 的验证矩阵在实际游玩中跑过一轮，含多人、重生、长时挂机
- [ ] 客户端扫描与锚固化的性能有**实测数字**（不是估算）
- [ ] `BACKLOG.md` 里不再有"未验证"标记的 P0/P1 条目

### 阶段 5 — 玩法闭环（下一步的大方向）
把"确定性"从技术优势变成玩法优势。核心是把**信息层**做出来：让玩家的观察产出可行动的预测。
候选条目（详见 `BACKLOG.md` P2-6 与 `DESIGN.md` §14）：

- 观察产出预测（手持模型右键给出"下一步最可能变成什么"）
- 碎片从"进度点"改为"新的感知维度"
- 回扫窗口随阶段增长，让阶段 1 真的有"逐渐"的体感
- 矿物退出突变目标池；失焦只产生错位、不产生价值
- 稳定有代价（容量 / 维护 / 会被侵蚀）
- 胜利条件不再能绕开王座与末地

**进入条件**：阶段 4 完成。**完成标志**：盲测新玩家在 2 小时内能自己说出"失焦有规律，我可以利用它"。

## 4. 长期目标

- **支持更多 Minecraft 版本**（最终目标 26.x）。
  `2026-09-21` 已做过一轮"版本可移植性重构"：落盘/过网的标识改字符串、
  后处理抽成 `ObserverVeil`、客户端镜像抽成 `ClientRegionData`、文本绘制收进 `VanillaText`/`VanillaGui`。
  升级 MC 前请先看 `PITFALLS.md` §9 的易碎点清单。
- **数据包可扩展性**：突变池 / 形态类 / 概念全部由标签驱动，
  目标是整合包作者不改代码就能调整失焦语义。
- **性能**：目标是在大视距 + 多模组环境下，客户端扫描与锚固化都不产生可感知卡顿。
