# 进度索引

> `docs/progress/` 是**已发生的事**的归档。每个文件记录一件事的**现象 / 根因 / 修法 / 验证**。
>
> 用法：**先按现象查**（下表），再点进对应小节。不要重新推一遍已经付过学费的坑。
> 想查"某个机制怎么运作"，去 `DESIGN.md`；想查"接下来做什么"，去 `BACKLOG.md`。
>
> 分卷规则：按时间/版本分卷（`ARCHIVE-<期间>.md`）。同一主题**就地更新**，不要新开一节流水账。
> 单卷超过约 2000 行时开新卷，并在本文件登记。

## 新增记录时

1. 先判断是**新主题**还是**已有主题**。已有主题 → 找到那一节，就地补充/更新，不要新开。
2. 四段结构：**现象 / 根因 / 修法 / 验证**。验证里必须分开写"已验证"与"未验证"。
3. 若结论具有普适性（换个地方也会踩），**提到 `PITFALLS.md`**，这里只留"当时发生了什么"。
4. 若产生待办，写进 `BACKLOG.md`，这里只放指针。
5. 在本文件的"按现象查"表里加一行——**这一行是最有价值的产出**，因为它决定了下次能不能被搜到。
