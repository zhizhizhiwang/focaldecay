## 1. 问题：三个抱怨，一个根因

作者原话：

1. 「失焦模式对玩家通关没什么关系」——像"我能在方块不断突变的情况下击败末影龙吗"这样的快餐题材；
2. 「玩家没有明确的目标」+「容易造成在基地里待到死」；
3. 「失焦会让珍贵的矿物块获取变得非常简单，而结束失焦后反而不行了」。

| 抱怨 | 机制上的根因 | 证据 |
|---|---|---|
| ① 失焦与通关无关 | 四个动词里只有**建造/破坏**有机制支撑；**观察**没有产出、**利用**只改落点、不改"是否发生" | `DESIGN.md` §13.3 自己标了 ⚠️；§14.6 |
| ② 没有目标 / 龟缩 | (a) 候选体的进度单位是"见过多少方块"（Pokédex），不是"理解了多少"；(b) 稳定系统与进度**同向**——越接近胜利越安全 | §13.5、§14.8 |
| ③ 矿物失衡 | **不是 `wild_chance`，是两件更硬的事**：<br>(a) **幽灵可挖**——挖幽灵方块拿的是**幽灵的掉落**（§5.2），所以"失焦"本身就是一条采矿路径；<br>(b) **概念跨 tier**——`focal_decay:concept/ore` 里同时有 `coal_ore` 和 `netherite_block` | §5.2；`src/generated/resources/data/focal_decay/tags/block/concept/ore.json` |

## 2. 主轴：三条规则

**R1 —— 词汇即样本。** 你能说的概念，只能来自你收集过的东西。**没有菜单，只有词汇表。**

**R2 —— 形可变，量不减。** 你能决定它**变成什么**，但不能减少**变化的总量**。
每一次定向失焦都在附近制造你控制不了的失焦；基地不可能同时是工厂与堡垒。

**R3 —— 阶段 3 开始，你的词会失效。** 后期不是"概率更高"，而是**概念本身开始漂移**：

```
drift  = 0.5 × t²        t = 阶段 3 内的归一化进度（增速递增，上限 0.5）
引导池 = (1-drift) × 你的概念 + drift × 邻近概念
q / 强度不变              界面显示「完备度 87% · 漂移 43%」
```

**你的模型没有变弱，是它的词被重新解释了。**

### 3.1 tier 的数据来源（实测，不是推测）

用 `jar tf` + `unzip -p` 读了实际标签文件（MC 1.21.1 client jar 与 NeoForge 21.1.248 jar）：

| 发现 | 事实 |
|---|---|
| **NeoForge 的 `c:` 里没有"高价值"标签** | `data/c/tags/block/` 下是材料分类。能拿来批量取材的是 **`c:ores`**（含 `c:ores/netherite_scrap`、`c:ores/quartz`）与 **`c:storage_blocks/<material>`** |
| **原版有等价物** | **`minecraft:beacon_base_blocks`** = 下界合金块 / 绿宝石块 / 钻石块 / 金块 / 铁块——原版对"贵重方块"的官方定义，可直接当高价值层的种子 |
| **`needs_stone_tool` 共 84 条，其中 76 条是铜** | `cut_copper` / `waxed_oxidized_copper_grate` / `copper_bulb` / `copper_door`… 即 **T1 有 90% 是廉价铜装饰** → 必须覆盖成 T0 |
| **`needs_diamond_tool` 只有 5 条** | `obsidian` / `crying_obsidian` / `respawn_anchor` 按获得门槛只是 T1（水+岩浆就能刷），真正属于 T3 的只有 `netherite_block` / `ancient_debris` |
| **信标确实不需要任何等级的镐子** | `beacon` 不在任何 `needs_*_tool` 里（实测 0 次命中）——正是作者点名的那一类 |
| **`needs_iron_tool` 的 12 条是干净的** | 钻石 / 绿宝石 / 金 / 红石 的矿与块，全部名副其实 |

> 因此 tier 的语义定为：**获得它的文明门槛**（不只看挖它要什么镐子）。
> `needs_*_tool` 只是这个语义的一个**便宜代理**；覆盖标签只修代理失真的地方。

## 4. 剩余待定：7 项参数与形式

> 方向不再重开。每项都给了**默认值**——可以逐条改数，也可以整体说"按默认"。

### P-1 tier 覆盖名单

三类已核实的错位，建议这样覆盖：

1. **铜装饰 → T0**（76 条，见 §3.1），保留 `copper_ore` / `raw_copper_block` / `copper_block` 在 T1；
2. **黑曜石 / 哭泣的黑曜石 / 重生锚 → T1**（T3 只留下界合金块与远古残骸）；
3. **高价值合成品 → T2/T3**：信标、潮涌核心、磁石、附魔台、铁砧、末影箱…（这批**原版没有任何标签**，只能手工列）。

取材种子：`minecraft:beacon_base_blocks` ∪ `c:ores` ∪ `c:storage_blocks/*` ∪ 手工枚举。

> **需要你定**：这三类之外还要补吗（刷怪笼、龙蛋、命令方块这类原版拿不到的）。

### P-2 "引导有小概率提升 tier"的数值

- 建议：**只在引导 / 催化下发生**（自然失焦不升 tier，否则裁定 8 白定）；
  `upTierChance = 0.05`，随 q 线性升到 `0.10`（q = 1.0）；**最多跨一级**（石头永远不可能直接出钻石）。
- **需要你定**：概率与"最多跨一级"这两个数。

### P-3 q 的分母规则（对应裁定 14）

1. **分母排除"拿不到的成员"**：没有 `BlockItem` 的方块不计入——
   `minecraft:frosted_ice` 正是这一类（实测：它是原版可突变方块里唯一没有 `BlockItem` 的），
   排除后 `ice` 概念 = 3 种，q 可以到 1.0；其余极难获得的用一张豁免标签兜底；
2. **大概念封顶**：`required = min(conceptSize_排除后, CAP)`，建议 `CAP = 16`——
   于是 `ore`（33 条条目，真实成员更多）只需 16 个成员即满，
   界面照实显示「已记录 16 / 需要 16（该概念共 33 种）」。

> **需要你定**：`CAP = 16` 是否合适；豁免标签要不要现在建。

### P-4 仪式的 tier 权限（裁定 11 的必然推论）

仪式**没有源方块**，"只降不升"无从判断。三个选择里推荐 (a)：

- **(a)（推荐）由模型的 q 分级**：`q ≥ 0.75 → 可产出到 T1`、`q ≥ 0.9 → T2`、`q = 1.0 → T3`。
  于是**理解深度 = tier 权限**，与 P-3、裁定 13、裁定 4 是同一条轴：
  想产一球铁矿**不需要"见过钻石"**，需要把这个概念理解得足够深。
- (b) 由额外投入的材料 tier 决定（付得起就行）——与"只降不升"的取向打架；
- (c) 不受 tier 限制——那它就是唯一的升 tier 通道，会让 P-2 的小概率升级失去意义。

> **需要你定**：选 (a) 还是 (b)/(c)；若选 (a)，三个阈值是否合适。

### P-5 候选体的达标条件（裁定 4）

- 建议：**N 个概念达到 q ≥ 阈值**（例如 **4 个概念 × q ≥ 0.75**），且这些概念要**分属不同材料族**，
  避免"四个都是石头类"这种取巧。
- **需要你定**：N 与阈值。（现在是"100 个唯一方块"；改成概念之后，§14.8 的绕行自动消失。）

### P-6 形式一的方块与道具形态（裁定 10）

- 建议：**催化剂方块**（放下即形成一个小的"待激发区"，界面能看到当前区域的概念与 q）
  + **火种道具**（右键催化剂点火，消耗耐久或充能）。配方在 P0 末期定。
- **需要你定**：是不是这个形态；"火种"要不要可重复使用。

### P-7 碎片在 P2 的具体补偿功能（裁定 17）

- 可选：每枚碎片降低 P-5 的 N 一个 / 允许"补一个拿不到的成员" / 解锁一种感官（§14.7 的旧方向）。
- **可以延后**：不影响 P0 开工。

## 6. 验收标准（第一刀 = P0）

- `[sync]` 段新增断言：**翻转催化域 → 两端解析结果跟着变**，并做 A/B（故意不翻转，断言必须 FAIL）；

## 7. 工程代价与硬约束

- **新增状态全部必须进同步**（§3.2 是最高优先级不变量）：催化域、漂移率、仪式序号。
  加任何客户端要用的值之前先问"客户端怎么知道它"。
- **可以复用的**（已读代码确认，不是推测）：
  - `MutationPoolManager.PrototypeEffect(center, radius, data, concept)` + 整表/增量同步 + 客户端镜像
    （`ClientRegionData.guidedModels`）——催化域是它的第三个字段，不是新管线；
  - `ThroneRitualHandler` 的状态机（CONTINUE / PAUSE / FAIL + 波次 + 进度持久化）——仪式直接复用；
  - `MutationHelper.resolveInternal(..., chance, wildChance, periodIndex, ...)` 里**"是否发生"就是 `chance` 一个 double**
    → 区域级 chance 覆盖**不需要新的判定分支**；
  - 回扫用的是 `MutationRandom.seed(pos, worldSeed, period)`，纯函数 → 催化**不破坏"两端逐位一致"**，
    也**不需要逐方块存档**。
- 沉降仪式的球体分布同样做成 `(pos, worldSeed, 仪式序号)` 的纯函数：可回放、可测、不落盘。
- tier 与 q 的新规则都落在**既有函数的输入侧**（池成员、概念规模），不新增逐方块状态。

## 8. 我会改变推荐的信号

- 若 P0 做完后玩家**仍然不知道该做什么** → 说明 R1 的可见性不够，该加的是**目标**而不是**答案**；
- 若催化让世界变得**太顺从** → R2 的溢出代价不够狠；
- 若玩家开始把基地当成**工厂**而不是研究站 → 裁定 5 的模型分工还没落到位；
- 若 tier 护栏让**前期太贫瘠** → 说明 P-1 的覆盖名单漏了东西，或 P-2 的概率太低；
- 若玩家把仪式当成**唯一的产矿手段**而不去挖矿 → P-4 的 q 阈值太低。
